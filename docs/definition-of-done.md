# Definition of done

## This specification/scaffold pass

- Repository inspected before editing, without Git commands or changes to Git metadata.
- README, ignore rules, non-secret environment template and the eight requested documentation files exist and agree on the question and scope.
- Useful empty directories support Python pipelines/geospatial/modelling, raw/interim/processed data, React/TypeScript, tests, documentation, reports and figures.
- Decision units, geographic levels, inclusion rules, target-age approximation, branch identity/validation, hypotheses, eligibility, finance, Pareto criteria, sensitivity and field contracts are specified.
- Unverified sources, missing numerical baselines and review decisions are explicitly recorded.
- Ignore rules cover environments, caches, dependencies, build products, secrets, macOS/temporary files and large/raw/generated data while retaining intentional placeholders.
- No datasets downloaded, websites scraped, dependencies installed, analysis implemented, dashboard built, fake findings generated or Git operations performed.
- No attribution files, repository-specific tool instructions or tool-specific notes created.
- Created documentation and paths checked for consistency. This is not a claim that data/model tests have passed.

## Eventual analytical completion

1. **Source feasibility:** verified sources, exact opened URLs and resource metadata, access/licence review and documented limitations. Resolve or explicitly narrow any missing critical input before analysis.
2. **Reproducibility:** Python 3.12 environment/dependency specification, deterministic stage commands, immutable snapshots or reproducible access instructions where redistribution is restricted, lineage and run/configuration records. Runtime setup is future work.
3. **National coverage:** every planning area represented or explicitly flagged; boundary/population vintages reconciled; screening decisions and node definitions auditable.
4. **Demand validity:** resident age proxy and allocation methods traceable, coarse-age assumptions disclosed, school context not double counted, catchment overlap and access limitations tested.
5. **Market validity:** separate brand/branch/offerings entities, validated confirmed and possible in-scope branch counts, geocode/deduplication audit, coverage uncertainty, a documented provisional competition-exposure method, per-1,000 diagnostic only and separate exploratory education-cluster context unless a confirmatory test is supported.
6. **Premises feasibility:** supporting units use exactly `verified_eligible`, `screened_feasible`, `ineligible` or `unresolved`. Public evidence and unit-specific authoritative evidence are separate. `screened_feasible` plus an evidenced cost scenario can support a conditional node shortlist with remaining confirmation visible; fully recommended or lease-ready premises require `verified_eligible`.
7. **Economics:** documented monthly inputs, contribution and staffing behaviour, capacity-constrained break-even, opening cash/working-capital needs and finite-horizon payback status. Expansion cannibalisation is an optional conditional analysis when adequate authorised operator data is available. Unset inputs cannot produce numeric results.
8. **Decision analysis:** transparent scenario-specific Pareto comparisons using provisional competition exposure as the primary competition criterion, no unexplained objective score, pre-results numerical definitions for H2/H3 materiality, an explicit plausible scenario grid, H4's 70% robustness test and honest explanation when fewer than three nodes qualify.
9. **Validation:** implemented critical checks from the data-quality plan pass; unresolved blockers prohibit release; accepted limitations are visible in outputs.
10. **Communication:** an analytical report explains methods, trade-offs, conditional recommendations and due diligence. Figures carry units, cut-offs and uncertainty. A React/TypeScript dashboard consumes validated precomputed data and supports accessible, intelligible comparison and evidence inspection; no decorative feature substitutes for analysis.
11. **Release integrity:** schema/version-consistent static outputs, no secrets/private pupil information, redistribution permissions established, source links rechecked, and narrative claims tied to actual calculations. No claims of validation for other subjects.

## Recommendation acceptance

For each scenario, publish up to three distinct commercial-node recommendations with complete critical comparison fields, a documented selection rationale, adverse-case outcomes and remaining due-diligence needs. A node backed by `screened_feasible` premises and an evidenced cost scenario is conditional and must state the final permission or landlord confirmation still required. A fully recommended or lease-ready premises requires `verified_eligible`. Separate `unresolved` investigation leads and exclude `ineligible` premises. Do not interpret Pareto membership or H4's scenario-grid frequency as a probability of success, and do not interpret stand-alone node comparisons as an optimal multi-centre rollout.
