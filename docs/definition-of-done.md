## Eventual analytical completion

1. **Source feasibility:** verified sources, exact opened URLs and resource metadata, access/licence review and documented limitations. Resolve or explicitly narrow any missing critical input before analysis.
2. **Reproducibility:** Python 3.12 environment/dependency specification, deterministic stage commands, immutable snapshots or reproducible access instructions where redistribution is restricted, lineage and run/configuration records. Runtime setup is future work.
3. **National coverage:** every planning area represented or explicitly flagged; boundary/population vintages reconciled; screening decisions and node definitions auditable.
4. **Demand validity:** resident age proxy and allocation methods traceable; local 800 m population and wider travel-time-accessible population remain separately labelled proxies, never unqualified addressable demand or customers; coarse-age assumptions and S5 overlap are disclosed; school context is not double counted; P1 balloting is not a core input; catchment overlap and access limitations are tested.
5. **Market validity:** separate brand/branch/offerings entities, bounded national discovery with coverage limits, complete manual validation of confirmed branches affecting shortlisted catchments, geocode/deduplication audit, resolved retained branches confined to the frozen geography, confirmed in-scope branch count as the primary competition measure, and per-1,000/distance/level-overlap diagnostics only. Publish `confirmed + all possible` only where possible-lead retention is complete. The completed national run did not retain possible leads systematically in every batch, so the final release preserves null upper bounds, records a warning and requires a zero-confirmed caution stress test; it must not invent a complete-market upper bound. Existing placement is revealed location behaviour, not proof of success.
6. **Node cost and optional premises feasibility:** conditional node recommendations state and sensitise a generic `operator_assumption` rent grid. S016 remains restricted manual context and is not reproduced, stored or used as a public analytical input. A current premises is not required. Optional unit due diligence uses exactly `verified_eligible`, `screened_feasible`, `ineligible` or `unresolved`; `verified_eligible` covers defined premises requirements only. Lease-ready claims additionally require current availability and quote evidence, while school/operator-registration and ordinary commercial/lease checks remain distinct and explicit.
7. **Economics:** the four core financial outputs are capacity-constrained `break_even_active_enrolments`, break-even utilisation, `required_capture_share` and `maximum_affordable_monthly_occupancy_cost`. Required-capture null/zero rules are enforced, and any later participation/capture assumption is a single illustrative combined parameter. Expansion cannibalisation is optional. Unset inputs cannot produce numeric results.
8. **Decision analysis:** quality/minimum-feasibility gates precede scenario-specific Pareto comparisons on exactly four dimensions; confirmed count is the primary competition criterion; multi-metric finance is combined within its dimension; all five frozen weight profiles are run; top-three frequency and rank distributions are published for every candidate; ties use median rank, worst-case rank and stable node ID; and fewer than three nodes are reported honestly. Only H1 and H2 are active; shortlist change is descriptive and robustness has no 70% pass/fail rule.
9. **Validation:** implemented critical checks from the data-quality plan pass; unresolved blockers prohibit release; accepted limitations are visible in outputs.
10. **Communication:** an analytical report explains methods, trade-offs, conditional recommendations and due diligence. Figures carry units, cut-offs and uncertainty. A React/TypeScript static dashboard consumes validated precomputed data and supports accessible, intelligible comparison and evidence inspection; no decorative feature substitutes for analysis.
11. **Release integrity:** schema/version-consistent static outputs, no secrets/private pupil information, redistribution permissions established, source links rechecked, and narrative claims tied to actual calculations. Mandatory generic output secret scanning blocks completion on any match. Exact-value comparison is supplementary whenever credentials are loaded; an otherwise clean cached run without credentials records a warning and limited assurance rather than failing. Findings persist only safe paths/counts. No claims of validation for other subjects.

## Recommendation acceptance

For each scenario/profile grid, publish up to three distinct conditional commercial-node recommendations using the frozen frequency and tie-break rules, with complete critical comparison fields, a documented rationale, stated `operator_assumption` rent values, rent sensitivity, adverse-case outcomes and remaining due-diligence needs. Do not imply a current unit is available, quoted, permitted, registered or lease-ready. If optional premises are presented, preserve all four statuses; a `verified_eligible` premises claim covers only the defined premises requirements, and a lease-ready conclusion also needs current availability/quote evidence plus separate operator/school and commercial/lease due diligence. Do not interpret Pareto membership or grid frequency as a probability of success, and do not interpret stand-alone node comparisons as an optimal multi-centre rollout.
