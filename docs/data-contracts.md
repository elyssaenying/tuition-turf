# Data contracts

Status: schema version `0.3.0`; the foundational working outputs listed below are populated by run `foundation_7dbd9a143e9504e7`. Analytical node, competitor, finance, ranking and dashboard tables remain unpopulated. The design contract still follows D31: two hypotheses, the primary competition count, generic occupancy-cost assumptions, inverse financial outputs, four-dimensional Pareto/ranking outputs and separate compliance layers.

## Shared conventions

- Stable IDs are strings. Names are labels, never join keys. Business entities and geography have separate IDs.
- Dates use ISO `YYYY-MM-DD`; timestamps use ISO 8601 with UTC offset. Every analytical run has `run_id`, `schema_version`, `method_version`, `analysis_cutoff` and source-snapshot references.
- Counts are nonnegative integers when observed; allocated population proxies may be nonnegative decimals and must not claim exact-person precision. Money is numeric SGD; monthly and one-time amounts have distinct fields. Shares are in `[0,1]`; utilisation may exceed 1 to signal infeasibility. Distances are metres and travel times minutes.
- `null` means unknown/not available and requires a `missing_reason`/quality flag. Zero means measured or calculated absence. IDs, table-grain keys, statuses and lineage references are non-null. Use JSON `null`; disallow NaN and infinity. A field required for a comparison may be nullable during processing, but then blocks that comparison.
- Geometry exchange is GeoJSON in WGS84, coordinate order longitude/latitude; projected working geometry records a verified metric CRS. Persist boundary vintage. Simplification must preserve IDs/topology and have documented tolerance.
- Each table grain below is unique per run/snapshot as applicable. Foreign keys must resolve; many-to-many relationships use explicit bridge tables. Multi-snapshot tables include snapshot IDs in their unique key.
- Field provenance uses `observed`, `calculated`, `proxy` or `assumption`. A calculated result based on proxies/assumptions retains those dependency flags; `calculated` does not imply empirically observed. Category belongs to the field/value, not indiscriminately to an entire row.

## Derived-field and release rules

Primary competition is `confirmed_in_scope_branch_count`. `competition_count_upper_bound = confirmed_in_scope_branch_count + possible_in_scope_branch_count`; it is a coverage scenario, not a statistically guaranteed bound on undiscovered branches. No fractional weights enter the primary criterion. Distance bands, level overlap, `direct_branches_per_1000 = 1000 × confirmed_in_scope_branch_count / accessible_target_population_proxy`, and any complex exposure are descriptive/secondary only; return null plus reason for a zero/unknown denominator or incompatible coverage.

`required_capture_share = break_even_active_enrolments / accessible_target_population_proxy`; do not clamp values above 1. Return null with `missing_input` if either input is null and `zero_proxy_population` whenever the denominator is zero, including zero divided by zero. `maximum_affordable_monthly_occupancy_cost` follows the methodology formula and returns null for missing inputs or target enrolment above capacity; a negative raw result is published as zero with `no_nonnegative_occupancy_cost_affordable`. Core node rents are `operator_assumption`; S016 observations never enter the public bundle. Transit reach and all remaining Pareto/release rules follow the methodology and decision framework.

The manifest and every bundled table must agree on run/scenario/schema versions. Later schema changes require a decision-log entry, version change and corresponding producer/consumer updates. Raw and generated tables remain absent in this pass.
